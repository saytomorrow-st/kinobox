## Задача

Переделать пробу в `MirrorPool` (появился в #005). Сейчас страница входа считается мёртвым зеркалом, но заказчик подтвердил, что часть зеркал показывает форму входа, и приложение работает только со входом. Нужны четыре состояния: `Open`, `NeedsLogin`, `Challenge`, `Dead` (таблица в `ARCHITECTURE.md`, раздел «Зеркала»).

## Ограничения

- `NeedsLogin` считается живым зеркалом. `Challenge` и `Dead` пропускаются.
- Куки привязаны к домену, поэтому `resolve()` возвращает зеркало вместе с признаком, нужен ли вход.
- Список известных зеркал по умолчанию: `https://kvk.pub/`, `https://rezka.fi/`. `rezka.si` не добавлять, пока заказчик не подтвердит, что домен официальный.
- Состояние `Challenge` определяется кодом из #009, дублировать его не нужно.
- `MirrorStore` не менять.
- Файлы: `mirrors.rs`, `examples/mirrors.rs`, `CRATE.md`.

## Готово когда

- Тесты wiremock на все четыре состояния, включая 200 со страницей входа и 200 с Anubis
- Руками: `cargo run -p kino-api --example mirrors -- --known https://kvk.pub/ --known https://rezka.fi/` печатает `LOGIN` для обоих зеркал, если у вас нет сессии (без VPN проверено 2026-11-14)
