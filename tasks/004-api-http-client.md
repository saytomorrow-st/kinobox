## Задача

`client.rs` в `kino-api`: HTTP-клиент на `rquest` с таймаутом, UA, retry с экспоненциальным backoff и jitter, хранением cookie. Повторяются только сетевые ошибки и 5xx/429, 4xx — нет.

## Ограничения

- Базовый URL приходит от `MirrorPool` (#005), в клиенте не хардкодится.
- Только публичные страницы. Никакого обхода DRM или платного контента.
- Тесты на `wiremock`, без реальной сети.
- Клиент возвращает `KinoError` из `kino-core`.

## Готово когда

- `cargo test -p kino-api client`: retry на 503, отсутствие retry на 404, соблюдение таймаута
- `CRATE.md` обновлён
- Руками: `cargo run -p kino-api --example fetch -- <url>` печатает статус, число попыток и первые 200 байт тела

## Заметки

Зависит от #001, #003. Если сайт отдаёт Anubis PoW-челлендж, клиент возвращает отдельную ошибку. Реализация PoW потребует `claude-opus-5-5` и идёт в отдельную задачу после согласования с заказчиком.

2026-11-13: `HttpClient` готов, 16 тестов на wiremock, `check`/`fmt`/`clippy`/обе архитектуры зелёные, example `fetch` проверен на https://example.com.
- `rquest` целиком yanked в crates.io (все версии), подключить нельзя. Взят преемник `wreq =0.16.3` (тот же автор). `ARCHITECTURE.md`, строка «Сеть», обновлена.
- MSRV поднят с 1.82 до 1.98 (требование `wreq`). Stable на машине 1.100.0.
- BoringSSL собирается под x86_64 и aarch64 без доустановки (cmake, clang, go уже стояли). Холодная сборка 5–6 минут. Риск из #001 закрыт.
- Имитации браузера (JA3/JA4) в `wreq` 0.16.3 из коробки нет: клиент ставит только `User-Agent`. Профили браузеров лежат в отдельном крейте `wreq-util`. Если HDrezka или Anubis смотрят TLS-отпечаток, понадобится отдельная задача. Узнаем при первом реальном запросе в #007.
- Встроенный retry `wreq` отключён, редиректы включены явно (до 10), иначе `attempts` врал бы.
- Anubis PoW не реализован: клиент возвращает `KinoError::Challenge`. Реализация потребует `claude-opus-5-5`, сначала спрошу заказчика.
- В сборке тестов и example есть предупреждение линкера про `btls-sys`, на результат не влияет.
- PR #4 открыт поверх ветки #003 (PR #3).
