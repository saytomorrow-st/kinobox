## Задача

Заказчик присылал `~/Library/Logs/app.kinobox.desktop/KinoBox.log` после сессии
тестирования (вход, попытка открыть серии, попытка воспроизведения — для багов
#1/#2/#5). Файл (114 строк, упёрся в ротацию 40 000 байт плагина) целиком
состоит из `[selectors::matching][DEBUG] Matching complex selector ...` —
сторонний HTML-парсер (`scraper`/`selectors`, зависимость `kino-api` для
парсинга страниц HDrezka) на уровне `Debug` печатает построчный лог матчинга
CSS-селекторов по всему DOM страницы. Это полностью забивает лог-файл и
ротацию (40 КБ), ни одно собственное сообщение приложения (команды, ошибки,
boot/login/player) не сохранилось — расследовать баги #1/#2/#5 по этому логу
было невозможно.

## Причина

`src-tauri/src/lib.rs::run()` — плагин `tauri_plugin_log` сконфигурирован
единым `.level(log::LevelFilter::Debug)` (в debug-сборке) без `level_for`,
поэтому Debug-уровень применяется вообще ко всем таргетам, включая
транзитивные зависимости (`selectors`, вероятно и `html5ever`/`tao`/`wry`),
а не только к своим крейтам.

## Исправление

`.level(log::LevelFilter::Info)` как общий уровень + `.level_for(...)` на
Debug (в debug-сборке) только для `kino_core`, `kino_api`, `kino_store`,
`kino_ipc`, `kino_player`, `kinobox_app` (имена пакетов с `-`→`_`, как их
видит `log`). Сторонние крейты остаются на Info и выше.

## Ограничения

- Не трогать остальную логику `run()`/`install_panic_hook()`.
- Файл логов и его путь (`~/Library/Logs/app.kinobox.desktop/KinoBox.log`,
  документирован в #026) не меняются.

## Готово когда

- CI (`ci.yml`) зелёный на коммите с фиксом.
- При следующем тесте заказчика лог содержит собственные сообщения
  приложения, а не только `selectors::matching`.

## Заметки

Найдено и исправлено lead-агентом (claude-sonnet-5) по прямому логу,
присланному заказчиком 17.11.2026, без делегирования — тривиальный
