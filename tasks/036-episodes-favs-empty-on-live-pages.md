## Задача

Пользователь (живой тест, после мержа фикса #030): «в сериалах всё так же
невозможно загрузить список серий». Фикс #030 (PR #34, замержен) добавил
извлечение поля `favs` из `#ctrl_favs` на странице деталей и передачу его в
запрос `get_episodes` — но по свежему лог-файлу (`~/Library/Logs/
app.kinobox.desktop/KinoBox.log`, сессия 17.11.2026) видно: во всех 3
реальных вызовах `cmd episodes` в этой сессии (media id 93174 дважды, 93428
один раз) итоговое значение `favs=(пусто)` — то есть `#ctrl_favs` на текущем
зеркале (`kvk.pub`) либо не находится вообще, либо находится, но даёт пустую
строку. Механизм фикса #030 технически работает (не паникует, не ломает
другие поля), но не достигает цели на реальных страницах.

## Расследование, которое нужно сделать первым

- Прочитай `crates/kino-api/src/parse/details.rs::extract_favs()` (добавлена
  в #030) — какой именно селектор используется, что происходит, если
  элемент не найден (должно быть тихое `None`/пустая строка, не паника —
  проверь это).
- **Нужна живая проверка реальной HTML-структуры страницы деталей на
  текущем активном зеркале.** Варианты получить её без запуска приложения:
  - explore-subagent может сделать `curl`/`fetch` страницы деталей сериала
    напрямую (публичная страница сайта, не требует авторизации для
    просмотра — но инструмент экспериментального HTTP-клиента может
    отсутствовать у субагента; если нет прямого доступа к сети зеркала —
    явно напиши в «Заметках», что живая HTML-проверка невозможна в этой
    среде, и предложи альтернативный диагностический путь).
  - Сверься ещё раз с референс-библиотекой `kristal374/hdrezka-api`
    (`HDrezka/movie_page_descriptor.py` или аналог) — как ИМЕННО там
    извлекается `favs`/`ctrl_favs`, есть ли альтернативные источники этого
    значения на странице (например, инлайн JS-переменная `sof.favs = ...`
    вместо `<input id="ctrl_favs">` — на HDrezka нередко значения строятся
    через инлайн-скрипт, не DOM-атрибут).
  - Проверь, не является ли сам `favs` опциональным параметром на некоторых
    конфигурациях сайта — то есть ответственен ли именно он за ошибку
    загрузки списка серий, или проблема в чём-то другом (другое
    отсутствующее поле формы, неверный `action`, устаревший `id` фильма).
    **Не гадай** — если расследование не даёт однозначного ответа, опиши
    находки и минимум 2 кандидата-причины в «Заметках», предложи, какую
    чинить первой, и явно попроси лид-агента/заказчика подтвердить перед
    тем как писать финальный фикс (вопрос допустим здесь — это
    неоднозначность в данных, не мелкий баг).

## Ограничения

**ВАЖНО — копия ограничений окружения заказчика из AGENTS.md, обязательна:**
Машина заказчика — слабый Intel Mac (i3-1000G4, 2 ядра, 8 ГБ ОЗУ, macOS
13.7.8). Запрещено `brew install mpv`/сборка `libmpv` из исходников вручную.
`src-tauri`/`kino-player` линкуют `-lmpv` — локальный `cargo check`/`test`/
`build` для них ЗАПРЕЩЁН; `kino-api`/`kino-core`/`kino-ipc` — разрешён
локальный `cargo check`/`test`. Запрещены `cargo tauri dev`, собранный
`.app`, `cargo run -p kinobox-app`, живой вход на HDrezka. Запрещены циклы
повторных прогонов «на всякий случай».

- Не выдумывай структуру HDrezka — если живую HTML-проверку сделать нельзя
  в этой среде, основывайся строго на референс-библиотеках

  пустым, залогируй это явно (не только финальный результат без контекста).
