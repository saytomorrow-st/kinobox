невозможно загрузить список серий». Фикс #030 (PR #34, замержен) добавил

## Заметки

### Расследование (2026-11-18, ветка feature/036-episodes-favs-fix)

**1. extract_favs() корректен и идентичен эталону.** Селектор
`input#ctrl_favs` → `value`. Отсутствие элемента — тихое `None`, пустой
`value` — `Some("")`, паники нет. Референс `kristal374/hdrezka-api`
(`player/movie_player_builder.py::PlayerBuilder.extract_favs`) использует
ровно тот же источник: `soup.find("input", id="ctrl_favs").attrs.get("value")`.
Альтернативного источника (инлайн `sof.favs = ...`) в эталоне НЕТ — гипотеза
не подтвердилась.

**2. Живая HTML-проверка невозможна из этой среды.** `kvk.pub` на анонимный
запрос отдаёт страницу входа (публичных страниц нет), `hdrezka.ag` закрыт
Anubis PoW. Уровень уверенности: средний — опираемся на эталон и фикстуры.

**3. Важная находка — эталон шлёт get_episodes БЕЗ favs, когда его нет.**
В kristal `extract_favs` возвращает `None`, если у инпута нет атрибута
`value`, и `requests` молча выбрасывает `None` из form-data. То есть
`favs` для `get_episodes`/`get_stream` **опционален** — пустое значение
вряд ли само по себе ломает запрос. Фикс #030 (DOM-инпут) технически верен.

**4. Настоящий корень неизвестен — провал НЕ логируется вообще.** В логе
сессии 17.11 после строки `серии: id=93174 translator_id=673 favs=(пусто)`
НЕТ ни INFO «N сезонов распарсено» (путь успеха), ни WARN «не распарсился
ответ» (путь JSON-сбоя: `success:false`, HTML-заглушка, Anubis-челлендж).
Значит ошибка возникала в `post_form` (сеть/челлендж/таймаут после retry)
или в отсутствии поля `episodes` при `success:true` — и в обоих случаях
уходила в UI через `?` без единой строки в логе. `commands.rs` ошибки тоже
не логирует, UI показывает generic ERROR_EPISODES. Реальную причину по
текущему логу определить невозможно.

**5. Подозрительная деталь:** во всех 3 вызовах разных сериалов
(93174/thriller, 93428/drama, 92497/horror) `translator_id=673` — один и
тот же «первый перевод». Либо это одна мажорная студия на всех трёх (возможно),
либо парсинг списка переводов на реальных страницах сериалов даёт неверный id.

### Кандидаты-причины (ранжированы)

- **A (предпочтительный): ответ get_episodes сбойный на сетевом уровне**
  (Anubis-челлендж на AJAX, редирект на страницу входа, таймаут) —
  соответствует полному отсутствию лога после отладочной строки.
- **B: `success:false`/не-JSON ответ** — но этот путь логируется WARN'ом,
  которого в логе нет → маловероятно (если только лог не потерян).
- **C: неверный translator_id** (парсинг списка переводов или init-аргов
  на реальных страницах сериалов) — сервер ответил бы `success:false` →
  был бы WARN → маловероятно по той же причине.
- **D: пустой favs** — по эталону опционален, слабый кандидат.

### Что сделано в этой ветке (диагностика, без угадывания фикса)

- `api.rs::episodes_list`: WARN при ошибке `post_form` (раньше — молчаливый
  `?`), WARN при `success:true` без поля `episodes`.
- `provider_impl.rs`: WARN в `episodes`/`streams`, когда `favs` пуст, с
  пояснением про поведение эталона.
- Тест `extracts_favs_from_real_film_fixture` на реальной разметке kvk.pub.
