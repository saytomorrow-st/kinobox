## Задача

Добавить сквозное структурированное логирование во всё приложение (facade `log` + `tauri-plugin-log` в `src-tauri`), чтобы заказчик после тестов на реальной машине мог прислать лог-файл, а lead-агент мог диагностировать баги без краш-репортов/угадывания.

## Контекст

Сейчас логирования нет вообще (`println!`/`eprintln!` только в CLI-примерах `kino-api/examples/*.rs`, нигде в основном приложении). Заказчик только что сообщил 4 свежих бага после установки (см. «Заметки»), диагностировать их без логов тяжело.

## Ограничения

- **Пароль никогда не логируется** — ни сырым текстом, ни в cookies, ни в заголовках запроса целиком (маскировать/обрезать). Это жёсткое требование безопасности проекта.
- Зависимость `log` (facade) можно добавлять в `kino-core`/`kino-api`/`kino-player`/`kino-store` — это внешний крейт, не нарушает правило "kino-core не знает ни о ком другом крейте".
- `tauri-plugin-log` подключать **только** в `src-tauri` (единственный крейт, которому разрешено знать о Tauri-плагинах).
- Не трогать границы крейтов/dependency-правила из `ARCHITECTURE.md`.

### Окружение заказчика — обязательные ограничения CI/локальной проверки

Машина заказчика — слабый Intel Mac (i3-1000G4, 2 физических ядра, 8 ГБ ОЗУ, macOS 13.7.8). На ней:

- **Запрещено `brew install mpv` и любая попытка собрать `libmpv`/`mpv` из исходников вручную**, в том числе как «обходной путь». На этой машине у `mpv` нет x86_64-бутылки в `homebrew-core` — сборка тянет полный граф зависимостей (вплоть до `llvm`) и может идти часами на двух ядрах.
- **`cargo check`/`cargo test`/`cargo build` с `-p kinobox-app`, `-p kino-player`, `-p kino-ipc` (или что-либо линкующее `-lmpv`) — запрещено запускать локально.** Это делает только CI (`gh pr checks` / `gh run list`, ждать `completed`). `kino-core`/`kino-api`/`kino-store` не зависят от `kino-player`, их `cargo check` локально допустим.
- **Запрещены циклы повторных прогонов** — один прогон, зелёный → готово, красный → осознанно чини и перезапускай один раз, не вслепую по кругу.
- Запрещены `cargo tauri dev`, собранный `.app`, бинарь `KinoBox`, `cargo run -p kinobox-app` — живой запуск приложения заказчика недоступен агенту вообще.
- Весь остальной workspace (`cargo check --workspace --exclude kinobox-app --exclude kino-player --exclude kino-ipc`, если такое разделение возможно) проверяй локально как обычно; финальную интеграцию (`kinobox-app`) — только через CI.

## Дизайн (решено lead-агентом, не переизобретать)

1. `src-tauri`: подключить `tauri-plugin-log` в `run()` (`src-tauri/src/lib.rs`), таргеты `Stdout` + `LogDir` (платформенная директория логов, на macOS это `~/Library/Logs/<bundle id>/`, bundle id — `app.kinobox.desktop`), уровень `Debug` в debug-сборке / `Info` в release. Добавить `std::panic::set_hook`, который логирует паники через `log::error!` перед завершением процесса (сейчас паника в Tauri-команде может просто завершать процесс без следа).
2. Остальные крейты используют только facade `log` (`log::info!`, `log::warn!`, `log::error!`, `log::debug!`) — никаких тяжёлых зависимостей, никакого `tracing`.
3. Точки инструментирования (приоритет — то, что уже сломано у заказчика, см. «Заметки»):
   - **Логин/сессия** (`kino-api/src/session.rs`): начало/успех/провал попытки входа с кодом причины; НИКОГДА не логировать пароль/полные cookies — маскировать.
   - **Каталог/детали/серии** (`kino-api/src/parse/*`, `kino-ipc` команды `catalog`/`details`/`episodes`): URL запроса (без секретных токенов), количество распарсенных элементов, и ОСОБЕННО путь ошибки — если парсинг списка серий проваливается, логировать HTTP-статус и фрагмент тела ответа, который не распарсился (это текущий баг заказчика: «ошибка загрузки списка серий»).
   - **MirrorPool** (`kino-api/src/mirrors.rs`): результат health-check по каждому зеркалу.
   - **Деобфускация потоков** (`kino-api/src/deobfuscate.rs`, команда `streams`): какие качества резолвятся, успех/провал.
   - **Плеер** (`kino-player/src/mpv.rs`, `src-tauri/src/player_state.rs`, `src-tauri/src/windows.rs`): жизненный цикл окна плеера (создание/attach/focus — текущий баг: «плеер выпал в отдельное окно с которым нельзя взаимодействовать», нужны логи create/parent/show/focus), вызовы mpv-команд (`loadfile`/`play`/`pause`/`seek`), и ОСОБЕННО код/строку ошибки mpv при провале запуска воспроизведения (текущий баг: «не удалось запустить воспроизведение»).
   - **Tauri-команды** (`src-tauri/src/commands.rs`): на входе/выходе каждой команды — имя команды + краткая сводка аргументов (без секретов) + результат (успех/ошибка с деталями).
4. Путь к файлу лога должен быть легко сообщаемым: вывести его через `log::info!`/`eprintln!` при старте (попадёт и в Console.app при живом запуске, и в сам файл), чтобы потом просто попросить заказчика прислать файл по известному пути.

## Готово когда

- `cargo check` зелёный для всех крейтов, не линкующих `-lmpv`, локально; `kinobox-app`/`kino-player`/`kino-ipc` — зелёный через CI (`gh pr checks`).
- Все точки из раздела «Дизайн» покрыты логами.
- Нигде в коде нет логирования пароля/токена сессии в открытом виде (проверить `grep` по commit diff перед PR).
- PR открыт по шаблону, лид-агент проревьюил и смержил в `main` (не дожидаясь доп. подтверждения заказчика — merge-first policy проекта).

## Заметки

Открыт в ответ на пожелание заказчика: «дай кому нибудь задачу написать полное логирование приложения, чтобы ты потом после моих тестов смог смотреть логи». Непосредственный повод — 4 свежих бага, обнаруженных заказчиком при первом реальном запуске собранного .app (после фикса багов #11/#12 в CI, mpv/ffmpeg AVFoundation):
1. Вход в аккаунт не спросил при первом запуске (ожидалось обязательное окно логина).
2. При открытии сериала — ошибка загрузки списка серий.
3. Плеер фильма открывается, но ничего не грузит — серый экран.
4. Плеер выпадает в отдельное окно, с которым нельзя взаимодействовать (похоже на баг embedding/parenting окна плеера).
5. На некоторых фильмах: «не удалось запустить воспроизведение. попробуйте еще раз».

Эти 5 багов будут расследоваться ОТДЕЛЬНО (не в этой задаче) — логирование нужно именно для того, чтобы следующий раунд тестов заказчика дал диагностируемый лог-файл вместо голого описания симптомов.
