## Задача

Сервисный слой `kino-ipc` для окна входа: состояние сессии, вход, выход, список зеркал с проверкой, ручное зеркало. Без зависимости от Tauri (тестируется wiremock и `MemorySecretStore`), DTO с `serde`. Тонкие `tauri::command` поверх сервиса и specta добавляет #015.

## Ограничения

- Пароль приходит в команду входа один раз и нигде не хранится: ни в состоянии, ни в событиях, ни в `Debug`, ни в ошибках для UI.
- В Keychain данные пишутся только после успешного входа (`login_and_remember`).
- Не менять `kino-api` без необходимости; если нужен метод, добавить минимально и обновить `CRATE.md`.
- Не обходить Anubis: зеркало с челленджем показывается в списке как недоступное.

## Готово когда

- `cargo test -p kino-ipc` зелёный, `cargo clippy --workspace --all-targets -- -D warnings` зелёный, обе архитектуры собираются
- `kino-ipc/CRATE.md` описывает команды и DTO

## Заметки

Первый запуск без сохранённых данных показывает окно входа. Сохранённые данные подхватываются молча.

2026-11-14: сервисный слой готов. 28 тестов `kino-ipc`, `fmt`/`clippy`/обе архитектуры зелёные.
- `AppService<S, M>`: `boot`, `login`, `logout`, `session`, `mirrors`, `check_mirrors`, `add_mirror`, `select_mirror`. DTO с `serde` (camelCase), `IpcError` с видами ошибок. Без зависимости от Tauri и specta, их подключает #015.
- Пароль принимается только в `login`, оборачивается в `Password`, в состоянии, DTO, JSON и ошибках его нет (тесты проверяют подстрокой, в том числе при эхе сервера).
- `boot`: нет данных -> `NeedsLogin`, данные приняты -> `SignedIn`, данные отклонены -> `NeedsLogin` с email и без удаления из Keychain, нет зеркал, Anubis или сеть -> `Unavailable`.
- `logout` пересоздаёт `HttpClient`, так как у него нет сброса cookie-хранилища; `kino-api` не менялся.
- Найден и исправлен нестабильный тест `mirrors_lists_known_without_requests` (падал около 5 раз из 60): помощник создавал mock-сервер для standby и сразу его освобождал, `wiremock` возвращает такие серверы в общий пул, и соседний тест получал тот же порт. Теперь standby указывает на закрытый порт `127.0.0.1:1`. После правки 0 падений из 100 прогонов.
- Живой проверки нет: все тесты на wiremock и in-memory хранилищах.
- PR поверх ветки #15 (docs/m2-plan).
