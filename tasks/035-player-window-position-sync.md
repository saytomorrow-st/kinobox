## Задача

Пользователь (живой тест): «окно плеера всё так же живёт своей жизнью» —
когда фокусируешь главное окно, окно `player` остаётся на месте, а
пользователь хочет, чтобы оно визуально «следовало» за главным окном
(двигалось/масштабировалось вместе с ним), но оставалось технически
отдельным окном (НЕ через AppKit `addChildWindow`/`WindowBuilder::parent()` —
это уже разобрано и отклонено в задаче #031: такая связь синхронизирует
минимизацию/закрытие, что не нужно). В fullscreen-режиме отдельный кадр
плеера допускается (точное поведение не specified — по своему усмотрению,
не блокирующий критерий).

Решение заказчика (подтверждено явным выбором): **синхронизация позиции** —
слушать события `Moved`/`Resized` окна `main` и программно двигать/ресайзить
окно `player` вслед за ним, без использования `parent()`/`addChildWindow`.

## Ограничения

**ВАЖНО — копия ограничений окружения заказчика из AGENTS.md, обязательна:**
Машина заказчика — слабый Intel Mac (i3-1000G4, 2 ядра, 8 ГБ ОЗУ, macOS
13.7.8). Запрещено `brew install mpv`/сборка `libmpv` из исходников вручную.
`src-tauri` линкует `-lmpv` — локальный `cargo check`/`test`/`build`
ЗАПРЕЩЁН, вся проверка — только через CI (`gh pr checks`/`gh run list`, жди
`completed`). Запрещены `cargo tauri dev`, собранный `.app`,
`cargo run -p kinobox-app` — живой запуск приложения запрещён в принципе.
Запрещены циклы повторных прогонов «на всякий случай» — один прогон CI,
зелёный — готово, красный — чини осознанно, перезапускай один раз.

- НЕ использовать `WindowBuilder::parent()`/AppKit `addChildWindow` на
  `player` относительно `main` — явно отклонено заказчиком (см. задачу #031,
  там же объяснение почему: синхронизирует minimize/close, а окна должны
  оставаться независимыми по интерактивности/фокусу).
- Логика синхронизации позиции: при открытии плеера (`open_player()` в
  `src-tauri/src/windows.rs`) подписаться на события `main` (`Moved`/
  `Resized`) и при каждом событии пересчитывать/применять позицию+размер
  `player` относительно `main` (например, сохранить смещение между окнами в
  момент открытия плеера, дальше применять то же смещение — не обязательно
  делать `player` того же размера, что `main`; выбери разумную схему и явно
  задокументируй в «Заметках», как она работает — абсолютно точная
  геометрия не критична, критично что плеер визуально «ездит» вместе с
  главным окном, а не остаётся висеть в старом месте).
- Подписку на `main` нужно снять/не триггерить лишний раз, когда плеер
  закрыт — не держать вечный обработчик, который двигает уже не
  существующее окно (используй существующий `shared: Arc<Mutex<Option<...>>>`
  паттерн или аналогичный способ проверить «плеер ещё открыт» перед
  применением позиции; при ошибке применения — `log::warn!`, не паниковать).
- Не трогай уже существующую логику `#031` (`Focused(true)` →
  `set_focus()` на `player-controls`) и `#027` (`center: true`,
  `set_focus()` после `show()`) — добавляй поверх, не вместо.
- Поведение в fullscreen — не блокирующий критерий, но если уводишь плеер за
  экран/ломаешь fullscreen своей логикой — это баг, проверь что синхронизация
  не применяется (или безопасно no-op) когда `main` в fullscreen.
- Не трогай unrelated части `commands.rs`/`tauri.conf.json`.
- Если публичный API `kino-player` не меняется — `CRATE.md` крейта не
  трогать; обнови `src-tauri/CRATE.md`, если меняется поведение открытия/
  связей окон (там уже есть раздел про #027/#031 — добавь продолжение).

## Заметки

Реализовано в `src-tauri/src/windows.rs`, функция `attach_player_sync` (#035).

**Схема синхронизации:** при открытии плеера (`open_player`) снимается смещение
`player` относительно `main` в физических пикселях и кладётся в статический
`PLAYER_SYNC_OFFSET: Mutex<Option<(i32, i32)>>`. На окно `main` один раз
навешивается обработчик `on_window_event` (флаг `PLAYER_SYNC_ATTACHED` —
`AtomicBool::swap`, чтобы при повторном открытии плеера не появилась вторая
подписка; окно `main` живёт дольше `player`). На каждый `Moved`/`Resized` окна
`main` обработчик ставит `player` в `main.position + offset`; размер `player`
не меняется — плеер «ездит» вместе с главным, оставаясь отдельным окном.

**Выключение:** при `CloseRequested`/`Destroyed` плеера offset сбрасывается в
`None` → обработчик остаётся, но делает no-op (дополнительно проверяется
`get_window(PLAYER)`). Ошибки применения — `log::warn!`, без паники.

**Fullscreen:** если `main.is_fullscreen()` — синхронизация пропускается
(безопасный no-op), при ошибке проверки fullscreen тоже пропуск. Геометрию
fullscreen не ломает, за экран плеер не уводит.

Логика #031 (`Focused(true)` → `set_focus()` на `player-controls`) и #027
(`center: true`, `set_focus()` после `show()`) не тронуты — `attach_player_sync`
вызывается поверх, после `set_focus()` плеера и до `open_player_controls`.

Проверка — только CI (`src-tauri` локально не собирается, `-lmpv`). Живой
GUI-тест: подвинь/измени размер `main` при открытом плеере — плеер должен
визуально следовать.
