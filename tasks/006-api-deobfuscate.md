## Задача

`deobfuscate.rs`: из ответа `url` получить `Vec<StreamQuality>`. Алгоритм строго из `ARCHITECTURE.md`: префикс `#h`, разделитель `//_//`, удаление известных мусорных токенов, base64. Затем разбор формата `[360p]url,[720p]url`. Необфусцированный `url` (без `#h`) разбирается напрямую.

## Ограничения

- Токены мусора лежат константой в одном месте.
- Ошибка декодирования возвращает `KinoError`, без паники и без `unwrap`.
- Нет сетевых вызовов, чистая функция.
- Не придумывать новые токены. Если реальный ответ не декодируется, `status: blocked` и вопрос заказчику.

## Готово когда

- `cargo test -p kino-api deobfuscate`: обфусцированный и обычный вход, пустой вход, битый base64, несколько качеств в одной строке
- `CRATE.md` обновлён

## Заметки

Зависит от #002. Можно делать параллельно с #004 и #005.

2026-11-13: `deobfuscate(raw) -> Result<Vec<StreamQuality>>` готова, 12 тестов, `check`/`fmt`/`clippy`/обе архитектуры зелёные, example `deobfuscate` проверен в обоих режимах.
- Алгоритм строго по `ARCHITECTURE.md`: `#h`, разделитель `//_//`, `JUNK_TOKENS`, base64 (padding необязателен), разбор `[метка]url,[метка]url`. Зависимость `base64 =0.23.1`.
- Проверена только на синтетических данных: тесты кодируют строки «в обратную сторону». Настоящего ответа HDrezka в репозитории нет, поэтому реальный формат подтвердится в #007 на сохранённых фикстурах. Если реальная строка не декодируется, задача уйдёт в `blocked` и я спрошу заказчика. Токены не придумываю.
- Неясности формата, которых нет в документе: повторный `#h` внутри строки не обрабатывается; пробелы внутри обфусцированной части ломают base64; запятая с `[` внутри URL режет разбор (в валидном URL `[` должна быть percent-encoded).
