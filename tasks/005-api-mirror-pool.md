## Задача

`mirrors.rs`: `MirrorPool` с порядком проб из `ARCHITECTURE.md`: активное зеркало, список известных, `https://standby-rezka.tv/`, ручной ввод. Probe с таймаутом 5с, параллельный health-check, пометка мёртвых зеркал, ротация при ошибке.

## Ограничения

- Хранилище активного зеркала скрыто за трейтом (`MirrorStore`) с in-memory реализацией. SQLite-реализация придёт в M2 из `kino-store`, зависимость `kino-api` -> `kino-store` запрещена.
- Трейт `MirrorStore` объявлен в `kino-api`, не в `kino-core`. Если окажется, что он нужен в `kino-core`, сначала спросить заказчика.
- Список известных зеркал лежит константой, редирект standby разбирается по `Location`.
- Тесты на `wiremock`.

## Готово когда

- `cargo test -p kino-api mirrors`: выбор первого живого, fallback на standby, исчерпание списка даёт `KinoError`
- `CRATE.md` обновлён

## Заметки

Зависит от #004. Актуальный список зеркал взять у заказчика или из проверенного источника, не выдумывать.

2026-11-13: проверка `https://standby-rezka.tv/` (GET, UA браузера): `200 OK`, без редиректа, страница `<title>Вход на HDrezka</title>` с формой `#loginForm` (POST `/ajax/login/`, поля `login_name`, `login_password`, `login_not_save`). Шаг 3 из `ARCHITECTURE.md` («редирект на актуальное зеркало») сейчас не работает.
- Ответ заказчика: «некоторые зеркала являются формой входа». Значит, `200` не доказывает, что зеркало живое: проба обязана отсекать страницу-заглушку входа.
- Списка рабочих зеркал в репозитории нет, выдумывать его нельзя. Пул принимает известные зеркала из конфига (по умолчанию пусто) и ручной ввод. Рабочий домен нужен от заказчика для #007.

2026-11-13: `MirrorPool` готов, 17 новых тестов на wiremock (всего 46 в `kino-api`), `check`/`fmt`/`clippy`/обе архитектуры зелёные, example `mirrors` проверен.
- Порядок проб по `ARCHITECTURE.md`: активное, известные, standby, ручной ввод. Зеркало живое при 2xx, непустом теле и отсутствии `LOGIN_STUB_MARKERS`. `Challenge` делает зеркало мёртвым с причиной.
- `MirrorStore` объявлен в `kino-api`, добавлен метод `clear_active()` (нужен для `mark_dead`). Реализация в `kino-store` в M2 обязана реализовать все три метода.
- `Response` получил поле `final_url` (нужно для редиректа standby).
- `MirrorConfig::default()` заменён на `MirrorConfig::new() -> Result`: в варианте субагента была `unreachable!()` в production-пути, что противоречит правилу PR-шаблона.
- Мёртвые зеркала хранятся в памяти пула, после перезапуска сбрасываются.
- Example делает по два GET на адрес (`health_check` + `resolve`), а не по одному. Запросов мало, на публичные страницы.
- Рабочего домена HDrezka в репозитории нет. Для реальных запросов в #007 он нужен от заказчика.
- PR #6 открыт поверх ветки #006 (PR #5).
